# Project Adoption Playbook

## 1. Inventory

Identify canonical location, owner, active baseline, release process, environments, tests, documentation, incidents, risks and duplicate copies.

## 2. Classify

Select project criticality and the minimum control profile. Do not apply R3 bureaucracy to a prototype.

## 3. Map, do not rewrite

Map existing mechanisms to the portable records. Preserve working project-specific commands behind adapters.

## 4. Add minimum control surface

Project Record, current status, architecture boundary, security contact, work package template, check/test entry points and release/recovery owner.

## 5. Establish baseline

Run existing tests, capture current limitations and record a reversible checkpoint.

## 6. Pilot one real change

Use the smallest representative R1 or R2 change. Measure friction and correctness.

## 7. Automate repeated work

Add golden paths only after observing actual repetition.

## 8. Accept adoption

The project owner accepts the operating model version, exceptions and migration backlog.

## Rollback

Adoption changes remain isolated from product behavior and can be reverted as one governed change set.
